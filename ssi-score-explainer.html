Step by Step
The Methodology

Each stage is designed to produce a fair, weighted score that treats every individual student response equally.

01
Raw Survey Responses
Students complete surveys on a 1–4 Likert scale across multiple organizational units — Academic Affairs, Library, Student Services, and more. Each response is recorded with:
respondent_id
campus / location
target_unit_id
source_column (question)
numerical_score (1, 2, 3, or 4)
02
Filtering — Likert Only
Before any calculation, two question types are excluded. Only pure Likert 1–4 questions contribute to the satisfaction index.
✕ Binary (yes/no) — max score ≤ 1 ✕ NPS 0–10 — score_rule = NPS_0_10
✓ Likert 1–4 — 1 < max score ≤ 5
The guard uses the maximum observed score per question column as a proxy for scale type — binary columns top out at 1, NPS at 10.
03
Per-Question Average
For every combination of (unit × campus × question), the arithmetic mean of all individual responses is computed.
col_avg = Σ scores / n responses
col_count = n (used in weighting)
This produces one average and one count per question per campus per unit.
04
Campus-Level Aggregate
All question averages for a unit at one campus are combined using a response-weighted average — not a simple mean of averages. This ensures high-response questions don't artificially dominate.
campus_avg =
  Σ (col_avg × col_count)
  ─────────────────────
  Σ col_count
05
Unit Satisfaction Index
Campus-level averages are combined across all campuses for a given unit, again weighted by the number of responses per campus. A campus with 1,000 respondents carries more weight than one with 50.
unit_score =
  Σ (campus_avg × campus_count)
  ──────────────────────────
  Σ campus_count
06
Global Satisfaction Index
The institution-wide SSI aggregates all unit-level sums into a single score. Excluded units (opted out of cross-unit reporting) are removed before this calculation.
global_SSI =
  Σ unit_sum (all eligible units)
  ─────────────────────────
  Σ unit_count (all eligible units)

From Responses

A concrete calculation using one unit across two campuses. All numbers are illustrative.

Academic Affairs
unit_id: 4 · 2 campuses · 3 questions

Question Campus Type Avg Score Responses (n)
Course Relevance Main Likert 1–4 3.60 150

Teaching Quality City Likert 1–4 2.90 83
Academic Support City Likert 1–4 3.40 84
Would Recommend Both Binary (0/1) 0.82 699
Steps 3–4 — Weighted campus averages
Main Campus
numerator = (3.60 × 150) + (3.20 × 148) + (3.80 × 149)
           = 540.0 + 473.6 + 566.2
           = 1,579.8
denominator = 150 + 148 + 149 = 447
campus_avg = 1,579.8 / 447 = 3.534
City Campus
numerator = (3.10 × 85) + (2.90 × 83) + (3.40 × 84)
           = 263.5 + 240.7 + 285.6
           = 789.8
denominator = 85 + 83 + 84 = 252
campus_avg = 789.8 / 252 = 3.134
Step 5 — Unit Satisfaction Index
3.39
Unit SSI Score
Academic Affairs — Unit Score
Both campus averages are combined with response-count weighting. Main Campus (n=447) outweighs City Campus (n=252), pulling the unit score toward Main's higher average.
unit_score = (3.534 × 447) + (3.134 × 252)
           / (447 + 252)
          = 1,579.7 + 789.8 / 699
          = 2,369.5 / 699 = 3.39
Good — above 3.20 threshold

Performance
Score Caching

Aggregating thousands of responses on every page load would be slow. Computed scores are cached after the first calculation and served instantly on subsequent visits.

📥
Report Requested
User opens the Report tab for a given survey.
→
⚡
Cache Check
System reads survey_quant_cache. If rows exist — serve immediately.
→
🔄
Cache Miss
Full aggregation runs via SQL RPC. Results written to cache for next visit.
→
📤
Scores Returned
Per-(unit, campus) averages delivered to the report dashboard.
Cache Hit
~40–200 rows read instantly. No re-aggregation. Typical response: <100ms.
Cache Cleared & Rebuilt
Triggered manually from Settings after a data re-import. The next report load re-runs the full aggregation and re-populates the cache.
